# Разработка и связь с VPS

Компонент `telegram-balancer` размещён в `AutmateStudio/balanser_tg`. Текущий рабочий каталог на VPS-104: `/home/ubuntu/Lidogen_telegram_balancer`.

1. Создать рабочую ветку, внести изменение и открыть PR в `main`.
2. Дождаться CI: проверок исходников и секретов, тестов и сборки, предусмотренных для компонента.
3. После объединения запустить **VPS sync** для полного SHA с успешным CI. Обновится отдельный checkout `/home/ubuntu/lidogen-repos/telegram-balancer`.
4. Переключение работающего приложения на этот checkout выполняется отдельным согласованным выпуском после проверки постоянных томов, `.env`, сессий и способа отката. Текущий pipeline приложения не перезапускает.

CI использует только одноразовые тестовые ресурсы. Секреты и runtime-файлы исключены из Git и Docker build context. Проверка секретов — Gitleaks 8.30.1 с проверкой контрольной суммы официального дистрибутива.

Для связи настроены отдельные ключи: VPS читает свой репозиторий с read-only deploy key, а ключ Actions на VPS ограничен командами проверки и синхронизации только этого checkout. Полный SSH-ключ сервера в GitHub не передаётся. Host key проверяется строго.

`VPS_LINK_ENABLED` включает проверку соединения в CI. Для неё нужны repository secrets `VPS_HOST`, `VPS_PORT`, `VPS_USER`, `VPS_SSH_KEY`, `VPS_KNOWN_HOSTS`. У workflow только права чтения репозитория; для проверки результата CI при ручной синхронизации добавлено чтение Actions.

Импорта workflow n8n, восстановления production-БД и автоматических production-миграций в pipeline нет. Исходники взяты из действующего контура; существующие ошибки тестов должны оставаться видимыми и блокировать синхронизацию через workflow до исправления.
